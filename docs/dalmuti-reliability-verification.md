## 실제 브라우저 검증 — 2026-10-05

빌드된 앱을 로컬 서버에서 실행하고 인앱 브라우저의 데스크톱 1280×720, 모바일 390×844·360×640에서 확인했다.

- 4인: 입장, 상대 제출·혼합 조커 표시, 패스→트릭 정리, 선 1~4장 선택, 3장 응답 제출, 연속 클릭 잠금, 새로고침 후 손패·턴 복구.
- 4인 한 라운드를 실제 UI로 마쳤다. 최종 제출 후 1위 관전 안내·점수, 결과 화면, 자동 다음 라운드, 새 직분 배치, 중앙 더미 초기화를 확인했다.
- 다음 라운드의 어릿광대 2장 혁명 결정에서 거절하고 세금 반환을 진행했다. 2장 선택 후 다른 등급을 눌러도 총량이 늘지 않았고, 최종 교환 후 손패가 복원됐다.
- 자연 카드 3장+어릿광대 2장을 5장 묶음으로 제출했다. J 0·1은 비활성, J 2는 선택 상태였으며 중앙에 `5장 · J 2장`이 표시됐다.
- 6·8인: 입장과 첫 트릭 진행, 상대 타일 배치, 모바일 손패 스크롤, 중앙 더미와 하단 도크를 확인했다. 8인 데스크톱은 4+3, 모바일은 3열이었다.
- 390×844에서 문서 크기도 390×844였다. 장수 선택 버튼은 44×44px였다. 360×640 스크린샷에서도 화면과 주요 조작 영역이 잘리지 않았다.
- 8인 카드 제출 직후 화면 크기를 바꿔 연출을 중단하고 재동기화했다. 손패는 10→8장, 중앙은 실제 제출한 2장으로 정착했고 다음 상대 행동이 진행됐다.
- 검사한 각 게임 탭의 오류·경고 콘솔은 비어 있었다. 기본 나가기 확인창에서 검증 도구가 멈춘 경우 Escape로 복구하고 새 탭에서 이전 방 이탈을 확인했다.
- 대기실이 선택한 5라운드를 10라운드로 표시하는 누락을 발견했다. 공용 공개 상태에 `roundCount`를 추가하고 소켓 설정 테스트 및 실제 6·8인 대기실의 5라운드 표시로 재검증했다.

모든 애니메이션 변형을 눈으로 확인한 것은 아니다. 대혁명·상인 교환·reduced-motion의 모든 시각적 변형, 실제 기기의 손가락 조작과 WAN 지연은 자동 검증 외에 별도 확인하지 않았다.

## 구현

- 서버가 재접속 유예와 자리 AI 대행을 관리한다. 여러 명 연결 끊김에 하나의 90초 기한을 사용하고, 일부 복귀만으로 정지를 풀지 않는다.
- 명시적 나가기는 자리를 유지한 채 AI 대행으로 바꾼다. 마지막 사람이 떠나면 저장소의 방과 타이머를 삭제한다. 최종 결과를 떠날 때는 결과를 변경하지 않는다.
- 정지 시 남은 턴/결과 대기 시간을 보존한다. 연출 ACK 뒤 다음 턴 시간과 결과 대기 8초를 시작한다.
- 마지막 제출, 마지막 패스, 세금, 혁명, 상인 교환의 이벤트 순서를 보존한다. 중복 제거·재동기화·fallback 후 화면은 최신 권위 상태로 수렴한다.
- 세금 장수 제한, 44px 장수/조커 선택 버튼, 혼합 조커 안내, 전송 중 재클릭 잠금, 대량 제출 조커 표시를 적용했다.
- 카드 이동은 플레이어/손패 앵커에서 중앙으로 연결한다. 트릭 보관·뒷면 교환·배분·혁명·결과는 순차 처리하고 Framer Motion 완료 콜백으로 ACK한다.
- AI는 응답 제출과 패스를 모두 관측하고, 공개 남은 패 수를 기록한다. 가상 상대도 묶음과 강한 카드/조커를 보존하는 합법 응답을 고른다.

## 자동 검증

- 코어: 종료 제출 및 교환 이벤트 보존, 혁명 순서, 공개 관찰 중복 방지, 대응/패스 통계, 조커 응답, 비공개 정보 제한.
- 실제 소켓: 연결 종료로 예약된 타이머를 Node mock clock으로 90초 진행, 늦은 자리 회수 거부, 나가기 후 손패/자리 유지, 방장 이전, 마지막 사람 방 삭제, 빠른 중복 제출 차단.
- 복구: 다중 연결 끊김, 부분 복귀, 만료 경계 복귀, 다른 사람 대기 중 명시적 나가기, 무제한 턴, 남은 시간 복원, 각 선택 단계에서 나가기, 구버전 저장 상태 복원, 전원 미복귀 삭제.
- 프레젠테이션: 역순/중복 이벤트, 스냅샷 선도착, 오래된 스냅샷, 마지막 카드 후 결과, 마지막 이벤트만 ACK, fallback 및 오래된 완료 콜백, 세금 제한, 조커 축약, 변환된 부모 좌표.

## 검증 한계

모바일 브라우저 화면과 주요 제출·패스·결과 흐름은 확인했지만, 실제 기기 터치 편의와 모든 모션 변형을 보장하지 않는다. DB 마이그레이션과 사람 행동 데이터 보정은 수행하지 않았다. 복구는 기존 저장 형식과 메모리 저장소 테스트로 확인했다. 운영 배포 완료 여부는 푸시 후 운영 `/api/health`의 커밋 해시로 별도 확인한다.
